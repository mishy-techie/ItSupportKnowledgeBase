# IT Support Knowledge Base

A hands-on collection of IT support projects, troubleshooting guides, and lessons learned. Each entry documents a real problem, how it was fixed, and how to stop it happening again.

**Who is this for?**
- **Hiring managers and non-technical readers:** See how I approach problems, document my work, and learn from mistakes.
- **Technical readers and peers:** Find step-by-step fixes, commands, and reasoning you can reuse.

---

## 🚀 Project Philosophy

This repository is not a collection of copied tutorials. Every entry is built around:

- **Practical application:** Things I actually built or fixed in a lab
- **Troubleshooting and problem solving:** How I diagnosed the issue, not just the answer
- **Documentation:** Clear write-ups someone else can follow
- **Automation:** Scripts that save time and reduce errors
- **Security awareness:** Safe practices built into every project
- **Continuous improvement:** Revisiting and refining past work

Where possible, I use labs, scripts, diagrams, and screenshots to show the work.

---

## 📖 How Each Entry Is Structured

Every guide follows the same template, so you always know where to find what you need.

| Section | What it answers | Plain-English version |
|---|---|---|
| **Prerequisites** | What do I need before starting? | The tools, access, and knowledge required |
| **Troubleshooting / Implementation** | What was wrong, and what did I do? | The investigation and the steps taken |
| **Resolution** | How was it fixed? | The final solution |
| **Verification** | How do I know it worked? | Tests that prove the fix is real |
| **Prevention** | How do I stop it happening again? | Changes, checks, or automation to avoid a repeat |
| **Lessons Learned** | What did I take away from it? | What went well, what didn't, what I'd do differently |
| **References** | Where did I get help? | Official docs and sources used |
